# 成长记录册印章识别规则

用视觉模型（DeepSeek-VL / Cursor 读图等）按下列规则识别图片，**不要依赖本地 OpenCV 数字 OCR 结果作为最终答案**。

## 何时使用

- 用户提供成长记录册盖章页照片/扫描件
- 要求输出每枚（或每组叠盖）章的盖法与四角数字
- 用户说「按印章规则识别」「读盖章处」

## 两种章

| 类型 | 外观 | 四角数字 |
|------|------|----------|
| 知章 | 蓝色方章，内有花+手托图案，四角内侧常有短斜线 | **要读**内侧四角手写数字 |
| 行章 | 黄色/金色圆章，内有三瓣花纹 | **不读**四角数字 |

## 盖法（按组判断，1–11）

纯知章：

1. **正向章**：单枚蓝方，图案正向  
2. **引导章**：单枚蓝方，旋转约 180°（图案倒置）  
3. **改进章**：两枚蓝方叠盖，一正一倒，倒章偏左上  
4. **知章二叠章**：两枚正向蓝方斜向/水平叠盖  
5. **知章三叠章**：三枚蓝方品字形叠盖  

纯行章：

6. **行章**：单枚黄圆  
7. **行章二叠章**：两枚黄圆叠盖  
8. **行章三叠章**：三枚黄圆品字叠盖  

知行组合：

9. **知行对章**：一蓝方压一黄圆  
10. **知行对章二叠章**：两对纵向叠盖  
11. **知行对章三叠章**：三对品字叠盖  

叠盖时按**整组外轮廓**算一组，不要把紧挨叠盖的拆成多组无关章。

## 四角数字（核心）

1. 数字写在**方章内侧四角**（斜线旁），不是章外。  
2. 常见只填 **三个角**（多为左上、右上、左下），右下常空。  
3. 叠盖组：数字写在**整组方章外接轮廓的内角**，不是每一枚各读一套（除非明显每枚都写了且用户要求分枚）。  
4. 看不清就填 `null`，禁止猜测。  
5. 输出用键名：`左上` `右上` `左下` `右下`，值为一位数字或 `null`。

## 读图顺序

1. 定位表格「盖章处」大列（右侧宽列）。  
2. **从上到下按行**，每行内**从左到右**。  
3. 每遇到一个盖印单元（单枚或一组叠盖）输出一条记录。  
4. 黄圆单独出现 → 行章系列；与蓝方贴在一起 → 知行对章系列。

## 输出格式（必须 JSON）

```json
{
  "page_note": "可选说明",
  "stamps": [
    {
      "row": 0,
      "col": 0,
      "method_id": 1,
      "method_name": "正向章（知章）",
      "zhi": 1,
      "xing": 0,
      "orientation_deg": 0,
      "corner_digits": {
        "左上": 1,
        "右上": 3,
        "左下": 2,
        "右下": null
      },
      "confidence": 0.9
    }
  ]
}
```

- `row` / `col`：从 0 起，仅盖章处内相对行列。  
- `orientation_deg`：仅单枚知章填 `0` 或 `180`；叠盖可 `null`。  
- 纯行章：`corner_digits` 四个键均为 `null`。

## 质量要求

- 先保证**行列顺序与章组划分**正确，再填数字。  
- 数字以肉眼可见的手写笔画为准，章角印刷斜线不是数字。  
- 最终以本规则 JSON 为准；可与本地 Python 检测框对照，但数字以视觉模型为准。

## DeepSeek 调用提示

对接 API 时：系统提示放入本文件规则摘要；用户消息附图片，并写：

> 请严格按成长记录册印章识别规则，输出 JSON（stamps 数组）。
